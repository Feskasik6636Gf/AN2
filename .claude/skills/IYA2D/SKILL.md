# /IYA2D — производство ролика

Скилл самодостаточный: весь движок лежит в папке скилла (`engine/`, `templates/`, `references/`). Путь к папке скилла указан в строке «Base directory for this skill».
Анализ референсов уже сделан: **не анализировать референсы заново**, сразу делать ролик.

Перед работой прочитай:
- `references/RULES.md` — 10 обязательных правил.
- `references/style.md` — стиль, монтаж и удержание.
- `references/engine-api.md` — формат проекта и шотов; списки локаций, персонажей, жестов, эффектов и звуков.

Общение с пользователем — по-русски, коротко и понятно.

## 0. Развёртывание (один раз в рабочей папке или репозитории)
Рабочая папка — корень текущего проекта или репозитория пользователя (`$W`). `$SK` — папка скилла.
```bash
SK="<Base directory for this skill>"; W="$(pwd)"
[ -f "$W/engine/director.js" ] || { mkdir -p "$W/engine" "$W/sfx" "$W/projects" "$W/renders"; cp -r "$SK/engine/." "$W/engine/"; cp "$SK/templates/RULES.md" "$W/RULES.md"; }
mkdir -p "$W/.github/workflows" && cp -n "$SK/templates/render.yml" "$W/.github/workflows/render.yml"
printf "node_modules/\nprojects/*/build/\n__pycache__/\n" >> "$W/.gitignore"
cd "$W/engine" && (node -e "require('playwright');require('three')" 2>/dev/null || npm install --no-audit --no-fund)
python3 -c "import numpy" || pip install -q numpy
python3 -c "import faster_whisper" 2>/dev/null || pip install -q faster-whisper
[ "$(ls ../sfx | wc -l)" -ge 70 ] || python3 sfx.py ../sfx      # звуки синтезируются за секунды
```
- Если Playwright не находит браузер: `npx playwright install chromium`. В облачной сессии Claude Code Chromium уже установлен.
- Демо для проверки: `mkdir -p ../projects/demo && cp "$SK/templates/demo_project.js" ../projects/demo/project.js && node render.js ../projects/demo --qc`.
- Если `faster-whisper` падает при открытии файла: в `transcribe.py` аудио уже читается через ffmpeg; нужен установленный ffmpeg.
- Развёртывание нужно сделать один раз и закоммитить (`engine/`, `sfx/`, `.github/workflows/render.yml`, `RULES.md`), чтобы рендер на GitHub Actions видел движок.

## 1. Приём задания
- Нужны тема ролика и **озвучка пользователя**: он записывает её сам, ты её не синтезируешь.
- Если озвучки ещё нет: напиши сценарий на выбранную тему, дождись записи и остановись.
  - Сценарий 1–3 минуты (или длину, которую назвал пользователь).
  - Структура: холодное открытие → «А что, если...» → нарастание → главы → поворот → финал и вопрос зрителю.
- Озвучка пришла: создай `projects/<slug>/` (slug латиницей) и скопируй туда файл как `voice.<ext>`.

## 2. Тайминги
```bash
cd engine && python3 transcribe.py ../projects/<slug>/voice.<ext> ../projects/<slug>/words.json small ru
```
Используй фразы и слова из `words.json`. Это единственный источник таймингов.

## 3. Раскадровка → `project.js`
Разбей озвучку на шоты по смысловым фразам, по 2–4 секунды. Каждый шот начинается и заканчивается на границе слов. Сумма `dur` должна совпасть с длиной голоса (последний шот добивает до конца).

Для каждого шота выбери:
- **локацию:** из списка или построй новую на `stage.js` в том же стиле;
- **персонажей:** готовых или из конструктора, возраст и роль под тему;
- **действия:** ходьба (`moves`), смена эмоций, жесты, предметы, позы. `talk` ставь ровно на слова реплики этого персонажа;
- **камеру:** всегда движется. Наезд или отъезд, `follow` за героем, `pan`. Крупные планы — `zoom 1.8–2.4` + `bgBlur`;
- **эффекты** на акцентах фраз (удар, деньги, эмоции, UI);
- **текст:** пузыри, заголовки, счётчики;
- **переход:** `whip`/`flash`/`fade` на сменах места или времени, в остальных случаях жёсткая склейка.

Ещё в проекте:
- музыка: `music:[[t0,t1,mood]]` по частям ролика;
- субтитры: `captions:{words:require('./words.json').words,group:4}`.

Чек-лист по `RULES.md`:
- в каждом шоте есть действие и движение камеры;
- ноги персонажей стоят на полу;
- масштаб задаётся только через `at:[X,Z]`;
- новый объект появляется каждые 5–10 секунд;
- холодное открытие в начале, закольцовка и вопрос в финале.

Если для сцены не хватает объекта, позы, локации или эффекта — дорисуй его в движке в том же стиле и только потом используй.

## 4. Контроль качества (обязательно)
```bash
cd engine && node render.js ../projects/<slug> --qc     # → projects/<slug>/build/qc_XX.jpg
```
Открой каждый лист и проверь:
- нет ли наложений и обрезанных голов или текста;
- не висят ли персонажи в воздухе;
- соответствует ли масштаб локации;
- живые ли эмоции, читается ли текст, не уехала ли камера за край сцены.

Исправь `project.js` и повтори проверку. Для сложных движений отрендерь кусок через `--from/--to` и посмотри кадры подряд: ноги не должны скользить, рывков быть не должно.
Покажи пользователю 1–2 контакт-листа одним сообщением. Если он не просил ждать, продолжай.

## 5. Рендер на GitHub Actions
Workflow: `.github/workflows/render.yml`. Он режет ролик на куски по 6 секунд, рендерит их параллельно на 40 машинах, сводит звук (голос, музыка с приглушением, фоны, эффекты) и собирает 1080p MP4.
```bash
date +%s > projects/<slug>/render.request
git add projects/<slug> && git commit -m "render: <slug>" && git push -u origin <ветка>
```
Пуш файла `render.request` запускает рендер. Также можно вызвать `actions_run_trigger` (`run_workflow`, `workflow_id: render.yml`, `inputs: {project: '<slug>'}`).

Дальше:
- следи за запуском через `actions_list` (`list_workflow_runs`), отчитывайся коротко;
- по завершении `git pull`: готовый файл будет в `renders/<slug>.mp4`. Если файл больше 95 МБ, он лежит в артефакте `final-<slug>`;
- проверь `ffprobe`: 1920×1080, 30 fps, есть аудио, длительность = озвучке;
- отправь файл пользователю (`SendUserFile`).

Если Actions недоступны, рендерь локально:
```bash
cd engine && node render.js ../projects/<slug> && python3 mix.py ../projects/<slug> && \
ffmpeg -y -framerate 30 -i ../projects/<slug>/build/frames/f%05d.png -i ../projects/<slug>/build/mix.wav \
 -c:v libx264 -pix_fmt yuv420p -crf 18 -c:a aac -b:a 192k -shortest ../renders/<slug>.mp4
```

## 6. Правки
Правь только затронутые шоты, перепроверь их через `--qc`, потом перезапусти рендер (новый `date +%s > render.request`).

## Формат
Всегда 1920×1080, 16:9, 30 fps. Другие форматы — только по прямой просьбе.
